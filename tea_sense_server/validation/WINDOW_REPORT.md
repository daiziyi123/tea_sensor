## 实际浏览器检查

临时服务HTTP18000/TCP19000，online_seconds=10，正式端口8000/9000未动。预览脚本tests/preview_dashboard.py每3秒通过实际TCP发送demo窗口，并预置明确的demo历史；服务在验收后已停止。

- 正常窗口显示55.72%、ADC窗口均值17548、有效30/30、参与28；最近记录接收时间连续间隔3秒。初始无真实设备时仍提示真实设备尚未接入，没有自动回填demo。
- 暂停发送后两次点击刷新：百分比不变，SVG内容完全相同，999个有效点且999个唯一记录id，没有重复追加；超过10秒变为“数据超时 · 历史最后值”，距接收秒数继续本地变化。
- 有效24/30、参与22时仍有结果，但同时显示“含6次采样失败”、ADC_POLL_FAILED及清理失败次数；未冒充全采样成功。
- 有效23/30、参与0时，百分比和ADC均显示“—”，提示“本窗口有效样本不足”，曲线在失败记录处断开，没有回填旧值或显示0%。
- 主动切换demo_backup_001：旧单点0显示0.00%，标明“历史单点采样 / 未提供窗口统计”，没有假称为3秒平均。设备与1小时/24小时筛选后卡片、曲线和记录保持同一设备上下文。
- 历史分页从100条加载到200条，DOM中200个唯一记录id，包含错误窗口及完整计数。
- CSV按钮点击未显示服务错误，但浏览器下载事件捕获超时，未取得本轮下载文件；不能声称浏览器保存文件已验证。鉴权CSV端点和生产C到服务器的CSV内容测试已通过。
